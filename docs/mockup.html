Proposals

  1. Session pane

    The pane follows the session as well as the scripts: the tool Claude is running now, the last few it ran, its subagents, and how full the context and the five-hour limit are. Uses the tool.call, turn.start and turn.complete hooks, $.agent.list(), $.ui.view and $.session.usage().

  2. Rows that expand

    Each job row is a button. Press it to open the file path, pid, start time and exit code under the row. Uses Button with onPress.

  3. Dismiss

    Remove a stalled or finished row. The pane count says how many are hidden and brings them back. Uses $.store.

  4. Notifications

    A toast in the terminal when a job finishes, and a system notification when one fails or runs for more than 2 minutes. Uses $.ui.toast and $.ui.notify.

  5. Ask Claude

    A failed row sends its last output to Claude as a prompt, and the conversation carries on from there. Uses $.prompt.submit.

  6. Time remaining

    After three steps, the average time per step gives an estimate beside the elapsed time. No mod API call: the poll already sees every change.

  7. Last lines of output

    The details show the job's last few lines. Uses a second file per job, written by the helpers: <script>-<pid>.log.

  8. Stop

    End a running job from its row, after a confirmation that names the job and its pid. Uses $.process.run.

Next proposals

  1. Usage bars on one row

    Each bar shares a row with its label and figures, so the context and five-hour bars take two rows instead of four. The label shortens to 5h limit to fit. Below 40 columns each bar drops back to a row of its own: drag the pane narrower to see it. Reads bodyColumns from the Pane props.

  2. Starting width

    The mod asks for 48 columns when it opens the pane, by passing columns to $.ui.open. Claude Code already lets you drag the docked pane to any width from 24 columns to 45% of the terminal, and keeps that width for later sessions; a width you dragged beats the request. Here, drag the pane's left edge, or focus it and press the arrow keys.

  3. One place for each figure

    Your status line script drops its second row, whose context, cost and five-hour figures the pane already shows, and moves +318 -8 up to the first. The mod adds those figures to its own status line only while the pane is closed, which it knows from isPlaced. The prompt hint keeps the permission mode and loses the two tips, through the PromptHint render hook. The freed row goes to the pane. Compare Footer As now with Trimmed, then try 100 columns.

  4. What an agent cost

    A finished agent shows its time and tokens, such as 0m 40s · 65.2k tokens, from the Agent tool's result (totalDurationMs, totalTokens). A running agent shows only its time, because $.agent.list() carries no token count. Claude Code's own list under the prompt shows live tokens, and no mod can hide that list.

  5. Machine row

    While a job runs, a row above the bars shows CPU load, GPU load and free memory, read from Windows performance counters by one typeperf process the mod keeps running under $.process.spawn. It warns when a busy CPU runs below its base speed (% Processor Performance under 100), which is what a temperature reading would have told you, and when the laptop is on battery.

  6. CPU per job

    Each running job shows the CPU its process tree is using, matched by the pid in its file name through the Process V2 counters and walked down through Creating Process ID. A job whose file has gone quiet while its processes stay busy reads as quiet, not stalled, like reindex.sh here. A stalled job whose process has ended says so. Below 40 columns a running job's CPU gives way to its name.

  7. Limit forecast

    When the last few readings say the five-hour limit runs out before it resets, its figures give the time, such as 82% · full by 14:39, in the warning colour. Otherwise they keep the reset time.

  8. Context added last turn

    The context figures end with what the last turn added, such as +12k, so a large file read shows up as soon as it lands. The mod takes the difference between the $.session.usage() readings at turn.start and turn.complete.

Not proposed: hiding Claude Code's agent list under the prompt, which has no render hook a mod can use, and CPU or GPU temperature, which this laptop exposes only through a kernel driver run as administrator. A rewritten prompt hint replaces Claude Code's line, and its live parts may stop updating, so that change needs testing first.

Not shown: shells Claude starts in the background. The tool.call hook sees one start, but the call returns at once, so the pane would not see it end. That needs testing before the pane promises it.

While a script runs, its file holds one line, <startedEpochSec> <step> <total> <label...>, in .claude/progress/<script>-<pid>.txt. When it finishes the line becomes <startedEpochSec> done <exitCode> <endedEpochSec>. A script with no step count writes a total of 0 and gets a spinner and elapsed time instead of a bar, like sync-fixtures.sh here. In a terminal narrower than 144 columns the pane does not open by itself, which leaves the status line, written at every width; /progress opens the pane at any width.
